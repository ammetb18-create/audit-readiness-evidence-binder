# Access Control Policy

## Purpose

This Access Control Policy defines general expectations for granting, reviewing, modifying, and removing user access to company systems.

The purpose of this policy is to support cybersecurity governance, reduce unauthorized access risk, and provide audit-ready documentation for access control practices.

## Scope

This policy applies to:

- Employees
- Contractors
- Temporary workers
- Administrative users
- Privileged users
- Third-party users with approved system access

It applies to systems that store, process, or provide access to sensitive business, customer, financial, operational, or security information.

## Access Control Principles

Access should be managed according to the following principles:

1. **Least Privilege**  
   Users should only receive the access required to perform their job responsibilities.

2. **Need-to-Know Access**  
   Access to sensitive data should be limited to users with a valid business need.

3. **Role-Based Access Control**  
   Access should be assigned based on approved roles, job functions, or business responsibilities.

4. **Approval Before Access**  
   New access should require approval from an authorized manager, system owner, or control owner.

5. **Periodic Review**  
   User access should be reviewed on a recurring basis to confirm continued business need.

6. **Timely Removal**  
   Access should be removed promptly when users leave the company or no longer require access.

## Access Request Process

Access requests should include:

- User name
- Job role or department
- System or application requested
- Access level requested
- Business justification
- Approver name
- Approval date

Access should not be granted without documented approval.

## Privileged Access

Privileged or administrative access should be restricted and monitored.

Privileged access requirements include:

- Approval from an authorized owner
- Multi-factor authentication where available
- Periodic privileged access review
- Logging and monitoring of administrative activity
- Immediate removal when no longer required

## User Access Reviews

User access reviews should be performed at least quarterly for sensitive systems.

The review should confirm:

- Whether each user still requires access
- Whether the access level is appropriate
- Whether privileged access is justified
- Whether inactive or terminated users still have access
- Whether remediation actions are needed

Evidence of access reviews should include:

- Access review report
- Reviewer name
- Review date
- Findings
- Remediation notes
- Sign-off or approval record

## Offboarding Requirements

When an employee, contractor, or temporary worker leaves the organization, access should be removed promptly.

The offboarding process should include:

- Notification from HR or management
- Deactivation of user accounts
- Removal of privileged access
- Review of shared accounts or group access
- Confirmation of access removal
- Documentation of completion

## Exceptions

Any exception to this policy should be documented and approved.

Exception records should include:

- Description of the exception
- Business justification
- Risk acceptance owner
- Expiration date
- Compensating controls, if applicable

## Evidence for Audit Readiness

The following evidence may support this control area:

| Evidence Type | Purpose |
|---|---|
| Access control policy | Shows documented access governance expectations. |
| User access list | Shows who currently has access to sensitive systems. |
| Access request approvals | Shows access was approved before being granted. |
| Quarterly access review report | Shows access is periodically reviewed. |
| Privileged user list | Shows administrative access is tracked. |
| Offboarding checklist | Shows access is removed when users leave. |
| Account deactivation logs | Supports evidence of timely access removal. |

## Control Owner

Suggested owner:

**IT / Identity and Access Management**

Supporting teams:

- Security
- Compliance
- HR
- System owners
- Department managers

## GRC Analyst Takeaway

Access control is a core audit readiness area because unauthorized or excessive access can create cybersecurity, privacy, fraud, and compliance risk.

This policy demonstrates how a GRC analyst documents access control expectations, identifies required evidence, supports control ownership, and prepares access-related documentation for audit review.
